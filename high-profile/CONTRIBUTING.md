# Contributing

Keep changes within the public-source research purpose. Start with the claim, evidence and time model before adding visualizations or ingestion automation.

1. Preserve durable IDs and published history. Add a migration rather than editing an applied one.
2. Supply a meaningful fixture and regression test for a new data contract. Label synthetic material at every public surface.
3. Keep source-specific acquisition outside the API and core model. Respect publishers' licenses, terms and rate limits.
4. Never use an AI assertion as evidence. Preserve original-language text and separate translated or normalized material.
5. Test the complete provenance chain, contradictory evidence, dates and failure states, not just successful rendering.
6. Run type checking/build, relevant tests and the browser workflow for interface changes. Check keyboard access, narrow screens and text contrast.
7. Document unsupported behavior honestly. Do not expose decorative controls or report unperformed tests as passing.

Use conventional TypeScript and parameterized PostgreSQL. Avoid new infrastructure unless measured requirements justify it. The product contains no targeting or operational planning features; contributions adding those are outside scope.
